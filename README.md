# Customer Data Cleansing & Deduplication

A Python pipeline that cleans, validates and deduplicates a customer master dataset, the kind of work done in **Customer Master Data (CMD)** and data-quality roles. It standardises messy records, rejects invalid ones with clear reasons, finds duplicate customers (exact and fuzzy matches), and produces an audit trail.

> All data in this repo is **synthetic** and generated by `src/generate_sample_data.py`. No real customer information is used.

## Problem

Customer master data collected from multiple sources typically has inconsistent formats (`+91 98765 43210` vs `9876543210`), mixed case, abbreviations (`UP` vs `Uttar Pradesh`), typos, invalid values and duplicate customers. This leads to failed deliveries, wrong invoices and unreliable reporting.

## What the pipeline does

| Step | Action |
|---|---|
| 1. Standardise | Trim/collapse whitespace, proper-case names, normalise company suffixes (`Private Limited` → `Pvt Ltd`), lowercase emails, strip phone to 10 digits, map state abbreviations (`UP`, `MH`...) to full names, expand address abbreviations (`Rd`, `Sec`) |
| 2. Validate | Email format, 10-digit Indian mobile (starts 6-9), 6-digit pincode, GSTIN format, missing mandatory fields (name, state). GSTIN state-code vs state mismatch and missing GSTIN are raised as **warnings** |
| 3. Reject | Records failing validation go to `rejected_records.csv` with the reason, for the data owner to fix |
| 4. Deduplicate | Blocks on phone / email / GSTIN / pincode, then scores name similarity (`difflib`). Matches are grouped with union-find |
| 5. Survivor rule | In each duplicate group the most complete record is kept (tie-break: latest `created_date`) |
| 6. Report | Writes clean data, a duplicate report and a quality summary |

### Duplicate matching rules

- Same **phone** + name similarity ≥ 0.80
- Same **email** + name similarity ≥ 0.80
- Same **GSTIN** (unique per business)
- Same **pincode** + name similarity ≥ 0.92 + address similarity ≥ 0.85

## Results on the sample data

| Metric | Value |
|---|---|
| Raw records | 308 |
| Rejected (failed validation) | 18 |
| Duplicate groups found | 40 |
| Duplicate records removed | 40 |
| **Final clean records** | **250** |
| Record count reduction | 18.8% |

The sample data was built with 250 true customers, 40 injected duplicates and 18 injected invalid records, and the pipeline recovers all three exactly.

## Project structure

## How to run

```bash
git clone https://github.com/<your-username>/customer-data-cleansing-deduplication.git
cd customer-data-cleansing-deduplication
pip install -r requirements.txt

python src/generate_sample_data.py   # optional: regenerate the raw data
python src/cleanse.py                # run the pipeline
```

To use your own data, replace `data/raw/customers_raw.csv` with a file that has the same columns.

## Tech stack

Python, Pandas, regular expressions, `difflib` (fuzzy matching).

## Limitations and next steps

- GSTIN is checked for **format** and state code only, not the checksum digit or live government verification.
- State mapping covers a subset of states; extend `STATE_MAP` for full coverage.
- Fuzzy matching uses `difflib`; for millions of records, consider `rapidfuzz` or a dedicated record-linkage library.
- Possible additions: a Power BI / Excel data-quality dashboard on the output files, and unit tests.
